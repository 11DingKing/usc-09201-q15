# 林地争议调解卷领域约定

项目面向集体林权改革与林下产业协作场景，业务记录需要区分来源、发生时间与当前有效版本。涉及个人、机构或敏感地点的信息只应向职责范围内的角色开放，所有对外结果都应能够追溯到采用的数据版本。

## 共建与分层

调解卷由司法所与林业站共同建设，调解员身份须隶属两机构之一方可写入。调解卷分五层保存：

1. **主体层**：申请人、被申请人、第三人及代理人授权；未成年人单独标注并关联监护人，家庭隐私以 `privacy_tags` 标记。
2. **争点层**：边界（`boundary`）、租金（`rent`）、历史口头约定（`oral_agreement`）等争点独立登记，可设举证期限。
3. **证据摘要层**：只保存证据摘要与收录时间；超过举证期限的证据**标记为迟到版本，不拒收、不覆盖**。
4. **调解方案层**：方案按版本保存，每个版本锁定其依据的卷宗版本（`basis_version`）与证据清单（`basis_evidence_ids`）。
5. **签收状态层**：逐当事人记录签收、拒签、留置送达；履行情况支持部分履行（含百分比）。

共识以**争点**为单位：可对单个争点单独达成共识，也可单独撤回；撤回保留历史记录。已履行完毕的争点不得撤回共识。

## 事件溯源与版本锁定

所有写操作（受理、登记、授权变更、陈述、证据、会议、方案、共识、签收、履行、移交诉讼、结案）都转换为只追加事件，事件带有序号 `seq` 与 SHA-256 哈希链。任意历史版本可通过 `load_at(case_id, version)` 重放；结案复核 `build_review` 可锁定到指定版本回放，回答“谁在何时同意了什么”。事后篡改任何事件数据都会使哈希链校验失败。

关键规则：

- **补充材料/更换代理人不覆盖旧记录**：陈述只追加，可通过 `supersedes` 链接上一版本；代理人更换时旧授权失效，但旧陈述仍归属原代理人。
- **并行调解互斥**：同一争点不得同时出现在两个未结束的调解会议中，会议结束后争点释放。
- **移交诉讼即锁定**：未解决争点移交诉讼时锁定整卷版本，记录随卷移交的证据与陈述清单；锁定后禁止一切写入（含授权变更与补充陈述）。
- **结案顺序**：仍有未决争点时必须先移交诉讼才能结案；全部和解可直接结案。

## 公开查询脱敏

公开接口（`/public/progress/<查询编号>`）只返回进度：争点类型与阶段、达成/未达成数量、履行百分比、迟到证据数量、是否移交诉讼或结案。以下内容一律不下发：当事人姓名（脱敏规则见 `service/privacy.py`）、证件号、联系方式、具体坐落（仅保留行政村/林班粒度）、陈述与证据内容、未成年人与家庭隐私标签。公开查询使用与内部卷宗号分离的随机查询编号，查无此号与无权访问返回相同形态，防止编号枚举。`assert_public_payload_safe` 在每次公开响应前自检敏感字段泄漏。

完整卷宗与结案复核仅面向司法所/林业站调解员（内部接口 `/api/...`）。
